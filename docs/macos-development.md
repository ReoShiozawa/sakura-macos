# macOS 移植版の開発

このブランチは、本家とは独立した非公式改変・移植版である。
公式 `sakura-editor/sakura` の `b1eef8a` を基準に、
基本設計書 `sakura_editor_macos_port_design.md` の M1〜M3 を段階的に実装する。

## 開発ビルド

Command Line Toolsだけでも、CMakeのUnix Makefilesで開発用AppKitアプリを生成できる。

```sh
cmake -S . -B build/macos -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/macos --parallel
ctest --test-dir build/macos --output-on-failure
open build/macos/ui/mac/SakuraEditor.app
```

ヘッドレスなコアだけをビルドする場合は次を使う。

```sh
cmake -S . -B build/macos-core \
  -DCMAKE_BUILD_TYPE=Debug \
  -DBUILD_TESTING=ON \
  -DSAKURA_BUILD_MAC_APP=OFF
cmake --build build/macos-core --parallel
ctest --test-dir build/macos-core --output-on-failure
```

arm64とx86_64を含むUniversal Binaryは次のように生成する。

```sh
cmake -S . -B build/macos-universal \
  -DCMAKE_BUILD_TYPE=Release \
  -DSAKURA_BUILD_UNIVERSAL=ON
cmake --build build/macos-universal --parallel
lipo -info \
  build/macos-universal/ui/mac/SakuraEditor.app/Contents/MacOS/SakuraEditor
```

Developer ID署名・公証による外部配布は未完了である。
公開準備・権利確認・配布前の手順は[RELEASING.md](RELEASING.md)を参照。
正規表現はmacOS SDKの`libicucore`を使う。他OSでポータブルコアをビルドする場合は
ICUの`uc`・`i18n`開発ライブラリが必要で、Windows向けにはvcpkg依存を宣言している。

## 現在の実装範囲

- UTF-16 `char16_t`を使うポータブルな論理行バッファ
- CRLF、LF、CRの行単位保持
- UTF-16コード単位の位置変換と、CRLF・サロゲートペアの分断防止
- 挿入、削除、置換、Undo、Redo、保存時スナップショット
- 論理行数・累積長を持つ永続AVLツリーで本文を管理する。新しい固定本文のコピー取得はO(1)。
  通常編集は変更行とO(log N)の経路を更新し、改行を含む編集も近傍だけを解析してsplit／joinする。
  後続の行vector移動・全索引再構築を避け、連続走査には線形時間の専用カーソルを使う
- CRとLFが新たに結合する編集も正規化してUndo／Redoを維持。
  複数箇所の編集は全変更の成功後に確定し、後半で失敗しても本文・履歴を変更しない
- UTF-8、UTF-16LE、UTF-16BEの厳密な読込・保存とBOM維持
- macOSのCore Foundationを用いたCP932（Shift_JIS）、EUC-JP、ISO-2022-JPの読込・保存
- 読み込んだ文字コードとBOMを文書ごとに保持し、保存時に同じ形式を既定として再出力
- UTF-8、UTF-16LE／BE、CP932、EUC-JP、ISO-2022-JPの文字コード指定、
  BOM有無、入力改行コード（CRLF／LF／CR）を文書単位で変更する設定パネル
- 指定文字コードでの明示的な再読込。未保存の編集がある場合は破棄確認を表示
- `ITextMetrics`を境界にしたPortable LayoutEngine（折り返し、タブ、UTF-16境界）
- Core Textのフォント計測を`ITextMetrics`へ接続し、通常表示時の文書サイズ計算に利用
- 結合アクセント、和文濁点、国旗、肌色修飾、ZWJ絵文字などの拡張書記素を分断しない
  折返し。Core TextではUTF-16単位幅の加算ではなく、まとまり全体の幅を実測する。
  クリック位置も結合文字の途中へ入らないよう調整。通常表示とIME未確定表示に共通適用
- C/C++、Objective-C、Swift向けの軽量シンタックス色分け（コメント、文字列、予約語、数値、プリプロセッサ）
- 数値Function Codeを使う最小CommandBus
- UTF-16境界を守る検索・置換（リテラル、ICUのUnicode正規表現、
  単語単位、折返し検索）。日本語・絵文字への`.`、文書先頭アンカー、
  先読み、零幅一致、キャプチャ参照を含む逐次置換と全置換に対応
- `NSDocument`による複数文書、Finder/Openパネルからの読込・保存
- 2秒間隔の外部変更監視。未編集なら自動再読込し、編集中なら再読込／別名保存／
  現在内容保持を選択。削除・移動時は別名保存または現在内容保持を選択
- 編集後2秒のアイドル時に、本文、元パス、文字コード、BOM、入力改行コードを
  原子的なバイナリplistへ保存する復旧バックアップ
- 異常終了後の起動時に、未保存文書を復元／後で復元／すべて破棄できる復旧ダイアログ
- 復旧plistの型・バージョン・文字コード・改行値を検証し、破損した最新データから
  過去世代へフォールバック（既定2、最大20世代）。復元後も同じバックアップIDを使い、
  メモリへ開いただけで元データを削除しない。明示保存／通常終了／破棄で自文書の世代だけを削除する
- 復旧保存は既定256MiBで一時書込み分も保守的に算入して制限し、容量・I/Oエラーを通知する。
  上限到達時も他文書や以前の世代を自動削除しない。共通設定「復旧」で世代数・容量を指定できる。
  別プロセスとquota・世代回転・削除を同じ排他区間で処理する。詳細は下の耐障害性の節を参照。
  各世代は個別に原子的保存するが、全世代の更新を一括トランザクションにはしていない
- macOSのインプレース自動保存は使わず、明示保存と独自復旧バックアップを使用
- Core Text描画の独自`NSView`
- 折り返し表示に追従する行番号ガターと現在行の強調表示
- 同一文書を共有する2ペイン分割表示（ツール > ウィンドウ分割、カーソルとスクロールは独立）
- C/C++、Objective-C、Swift、Markdownの構造候補を一覧化し、選択行へ移動するアウトライン解析パネル
- 使用可能なメニュー操作とショートカットを列挙し、選択操作を実行するコマンド一覧パネル
- Windows版のタイプ一覧に合わせた「タイプ別設定一覧」と、6ページ構成のタイプ別設定パネル
- Windows版の設定分類に合わせた10ページ構成の共通設定パネル
- 共通設定からエディタのフォントサイズとTAB幅を永続化し、開いている全ペインへ即時反映
- タイプ別設定「スクリーン」「ウィンドウ」から、折返しなし／ウィンドウ幅／指定桁数、
  TAB幅、行番号表示、フォント書体・サイズ、行間、文字間隔を保存し、同じタイプの
  全ウィンドウ・分割ペインへ反映。適用、OK、キャンセルに対応
- スクリーンタブの「画面設定を既定に戻す」で、タイプ別画面設定を未保存状態へ戻し、

- Windows版の`ColorInfo_DEFAULT`に合わせた既定配色（暖色系本文背景、青い行番号と
  現在行下線、緑のコメント、青のキーワード、検索・選択色）
- 共通設定から「Windows クラシック」「macOSの外観に合わせる」「ダーク」を選択し、

  元の文字コードとBOMの維持、原子的な保存、既定の`.bak`バックアップ、
  開いている文書の競合回避、処理中止に対応
- Grep置換は検索時に原文・ファイル実体・置換結果を固定し、実行時の再走査をしない。
  外部変更・パス差し替えは保存直前まで原文とメタデータを照合してスキップする。
  バックアップは保持した原文から作り、`.bak`・`.bak.N`を候補から除外する。
  候補保持は128MiBまでで、上限・検索中止・読込変換エラー時は置換実行を無効にする
- Grepの件数上限は検索結果の生成段階から適用し、正規表現評価の中止・時間制限と
  置換文字列展開量の上限を設ける。保存結果と競合・編集中・エラーをファイル別に表示する
- 本文文字列、表示行、構文解析、検索結果を変更依存でキャッシュし、文字装飾は可視行ごとに
  最大256行／8MiB目安のキャッシュへ保持。選択の変更は別の装飾として重ねる
- 再描画ではdirty rectangleに交差する表示行だけを走査。表示行の位置検索は二分探索を使い、
  ウィンドウサイズ計算でも全行のCore Text再計測を繰り返さない
- 通常文書・日本語文字コード・Grepファイル保存・エディタ選択移動・検索置換・
  Grep候補から実行・画面設定・描画キャッシュなどの自動テスト。

  行数、sliceを照合し、改行結合、copy／move、alias入力、失敗時の状態保持も検査する。
  AppKitテストは画面を表示せず、描画先はメモリ上のbitmap。本家との完全な等価試験ではない
- 公開準備のソース・バンドル検査、チェッカーの10件の正常系／拒否系試験、
  非公式版メニュー・About情報の画面非表示テスト。Pythonが利用可能な構成では
  機能テストを含む。現在の構成と検査範囲は後述の単一置換の確認を参照。
  法的な権利監査・署名検証の代替ではない

## 日常編集コマンドの追加（2026-10-25）

- ⌘Lの論理行ジャンプ、ブックマーク設定／解除・前後移動・全解除・一覧。
  前後移動は文書端で循環し、行番号欄へ青いマーカーを表示する。
  ブックマークは文書所有で分割ペイン間で共有する。再起動時の永続化は未実装。
  編集ごとの共通接頭辞／接尾辞でUTF-16アンカーを補正し、置換・削除された範囲の
  アンカーは変更開始位置へ寄せる。行ソート時の内容追跡や、削除後Undoでの
  マーク元位置の厳密な復元を保証する方式ではない。ブックマークがある文書では
  変更時に比較用の本文コピーが必要で、巨大文書での性能は今後の課題。
- TAB／SPACEインデントと逆インデント、先頭／末尾の半角空白・TAB削除、
  昇順／降順ソート、連続重複行削除、改行単位の行二重化。
  選択なしは現在の論理行、選択ありは選択が触れる論理行が対象。
  選択末端が次行の先頭なら次行を含めない。矩形選択への行操作は拒否する。
  ソートはロケール非依存の文字列比較で、日本語の読み順／数値順ソートではない。
  改行は元のスロットを維持し、末尾改行の有無も保持する。重複削除は最後の
  改行状態を引き継ぐ。行二重化はEOFに改行がない場合のみ入力改行を補う。
- 範囲選択中のTABは行インデント、Shift＋TABは逆インデント。
  カーソルのみのTABと矩形入力は従来の文字挿入を維持する。
- 全角→半角、半角＋ひらがな→全角カタカナ、半角＋カタカナ→全角ひらがな、
  TAB⇔空白。幅／かな変換はCore Foundationの変換規則によるもので、
  Windows版の変換テーブルとの全入力等価性は未検証。矩形選択の文字変換にも対応。
  TAB変換は行頭からのTAB位置を計算し、結合文字をまとめ、和文・標準絵文字を
  2セルとして扱う。任意の比例フォントの実測描画幅とは一致しない場合がある。
- 新規21コマンドをメニューへ接続し、既存の単語・ページ・折返し行移動と
  範囲選択14項目の無効メニューを実際のハンドラーへ接続した。
  テキスト変更は単一Undo／Redo、同一結果の通常操作は履歴を追加しない。
- 復旧データの文字コード値の桁あふれ／小数値を拒否し、シンボリックリンクや
  256MiB超の復旧ファイルは読み込まない。

## ファイル操作と追加編集（ローカル開発版）

- 「すべて上書き保存」は開始時点の文書を順次処理し、未変更文書や待機中に
  閉じられた文書は飛ばす。未保存文書の保存先指定にはNSDocumentの標準処理を使い、
  キャンセル・失敗・保存後の新しい編集があれば残りの保存を停止する。
  二重実行を防ぎ、文書数に比例した再帰呼出しを避ける。すでに保存した文書は戻さない。
- 「保存して閉じる」は保存成功後、文書が未編集の場合だけ閉じる。
  保存中に編集が増えた場合は閉じず、復旧バックアップも削除せず再保存を予約する。
  保存準備時に各ペインのIME未確定文字列を文書へ確定してからdirty判定／snapshotを作る。
- 「最近使ったファイル」はNSDocumentControllerの履歴から最大20件を動的表示する。
  フォルダー履歴はその親フォルダーを重複除去したもの。選択すると該当フォルダーを
  初期位置にしたファイル選択パネルを開く。Windows版の独立したフォルダー履歴ではない。
  ファイルURLだけを扱い、履歴消去も標準コントローラーへ委譲する。
  ウィンドウ内へコピーしたメニューも、開く際に最新の履歴へ更新する。
- 日付（yyyy/MM/dd）・時刻（HH:mm:ss）挿入、現在単語の選択／削除、左右の単語端まで削除、
  論理行頭／末まで削除、論理行削除を実装。日時は端末のローカル時刻を使い、
  書式カスタマイズは未対応。文字削除は既存のUnicode／CRLF境界保護を使う。
  行削除は改行を含め、最終の改行なし行では直前の改行も一緒に削除する。
- ファイル名・パス・パス＋1始まりの行／UTF-16桁のコピー、CRLF改行でコピーを実装。
  CRLFコピーは文書の改行を変更せず、矩形コピーの行末仮想空白も維持する。
  無題文書でのパスコピーは既存クリップボードを変更しない。
- 前回追加分を含む新規編集操作と一括保存をコマンド一覧へ接続した。
  テストでは保存完了コールバック、キャンセル、I/O失敗、保存途中の編集、IME確定、
  メニュー複製・履歴上限と更新、単語／行削除のUndo、日時・コピー内容を検証する。
  テストは専用一時ファイルとダブルを使い、ユーザーの履歴・クリップボードを変更しない。

## 基幹機能の拡張（ローカル開発版）

- 通常検索の大文字小文字無視をASCII限定からICUのUnicode full case foldingへ変更。
  `Straße`／`STRASSE`のように一致長が異なる場合も原文のUTF-16位置を返す。
  リテラルのメタ文字や`$1`を正規表現として扱わない。結合文字・補助平面の文字・
  数字・コネクターを単語構成要素に含める。自然言語の辞書的な単語分割ではない。
- 正規表現の`^`／`$`は既定で行単位に一致する。`\A`／`\z`は文書アンカーのまま。
  コアAPIはmultilineを無効にもできる。文書全体のlookaround文脈、零幅一致、
  検索中止・時間制限・置換量上限は従来どおり維持する。
- 22言語モード＋プレーンテキストへ字句色分けを拡張。C/C++、Objective-C、Swift、
  Java、C#、JavaScript、TypeScript、Python、JSON、Shell、Ruby、SQL、HTML、XML、
  CSS、Markdown、YAML、TOML、INI、Go、Rustを拡張子から選ぶ。
  コメント、引用文字列、複数行／raw文字列、予約語、数値を既存のタイプ別配色へ接続。
  HTMLのscript/style、Markdown見出し・コードフェンス・基本リンク／強調、
  YAMLブロックスカラー、Shellの単一ヒアドキュメントも字句レベルで扱う。
  IME中は表示用の一時bufferを色分けし、確定本文へは書き込まない。
  未知拡張子は色分けせず、プレーンテキストを構文解析用に全文コピーしない。
- アウトラインはコメント・文字列をマスクし、Python、JS/TS、Rust、Go、Ruby、Shell、
  SQL、Markdownの宣言パターンを追加した。複数行コメントやコードフェンスの中の
  偽の見出し／関数宣言は拾わない。C系は従来の軽量候補抽出を継続する。
- Grepに単語検索と7種類の入力選択（自動、UTF-8、UTF-16LE/BE、CP932、EUC-JP、
  ISO-2022-JP）を追加。BOMなしUTF-16の明示指定では生バイトのNUL判定を使わない。
  単語・文字コード条件は保存し、変更時は古い置換候補を使えないよう署名に含める。
- ファイルパターンは`;`等で複数指定でき、`!`で名前を除外する。
  例`*.js;*.ts;!*.min.js`。除外のみなら他の名前をすべて対象にする。
  除外フォルダーとは別機能で、Windows版の全パス指定構文ではない。
- Grep結果をUTF-8テキストで書き出す。実行途中ならその時点の結果・状態を固定する。
  ジャンプ前と読込後にファイルの実体・サイズ・変更時刻・ctime等を照合し、
  検索後に変わったファイルや編集中の文書には古い位置でジャンプしない。
  文字コードが違う未編集文書は検索時のコードで再読込する。非協調プロセスによる
  最終照合直後の変更まで排除する保証ではない。
- 32MiB超のファイルとバイナリの除外件数を表示し、大容量ファイルを除外した検索から
  不完全なGrep置換を実行しない。件数20,000・候補128MiB等の安全上限は継続する。

本家キーワード／Windows色定義ファイルの全仕様互換、
全言語の構文解析／文字列補間／正規表現リテラル、JSX/TSX固有のタグ構文、
言語方言の完全対応、複数ヒアドキュメント、複雑なMarkdownの全仕様、
インクリメンタルな色分け・アウトライン解析、巨大ファイルの無制限Grep、
本家Bregonig/Onigmoとの完全互換、権限エラーを含む全探索の網羅性は未達。
言語対応表や自動テスト成功を「本家の基幹機能をすべて完全実装」とは扱わない。

### タイプ別の追加キーワード・正規表現

- タイプ別設定「正規表現キーワード」の仮表示を実際の編集パネルへ置き換えた。
  追加単語は空白／改行区切り、正規表現は空行を除く1行1ルール。
  正規表現の先頭／末尾の空白は意味があるため削除しない。CRLF／CRは行区切りへ正規化する。
  大文字小文字の区別もタイプ別に保存する。本文や既存のUndo履歴は変更しない。
- 適用／OKで検証して保存し、取消し／閉じるでは下書きを保存しない。
  不正なルールは他の画面設定も含めて適用を中止し、該当タブでエラーを表示する。
  複数パネルでは編集したフィールドだけを最新の保存値へマージするため、未編集の
  古いキーワード値が別パネルの確定済み変更を巻き戻さない。画面設定のResetとは独立する。
- キーワードはUnicodeの単語構成文字のみ。大小文字無視にはUnicode full case foldingを使う。
  最大2,048語、1語128 UTF-16単位、合計32,768単位。正規表現は最大8件、各512単位。
  コメント・文字列・数値・組込みキーワード等の既存トークンを保護し、追加単語を優先、
  その後は正規表現の記述順で重なりを解決する。零幅一致は描画トークンを作らない。
  キーワード1〜10へ分け、各グループの色／背景／太字／下線／表示を個別に設定できる。
  組込みの言語キーワードはグループ1のまま、追加単語はグループ番号順で優先する。
  その後にグループ番号順・ルール記述順で正規表現を評価する。数量上限は全グループ合計。
- 描画スレッドでは正規表現を実行せず、75msの入力休止後に固定した本文とルールを
  バックグラウンドへ渡し、通常色分けの完了後に追加ルールを評価する。
  本文変更・IME更新・設定変更後の古い結果は世代と本文rootを照合して破棄する。
  結果は追加トークンだけで、本文・保存状態へ書き戻さない。通常の言語色分けは先に表示する。
- 文書上限は2Mi UTF-16単位／100,000論理行、追加一致は10,000件。
  ICUの1パターンの時間上限は50ms、追加の検索・一致評価は合計200msを目安に中止判定する。
  ICUの時間制限はハードリアルタイム保証ではない。上限／エラー時は部分的な追加色を使わず、
  通常の色分けを維持してステータスバーへ状態を表示する。編集と保存は継続できる。
  サイズ上限は通常の言語色分けやファイルを開く上限ではなく、この追加処理だけの制限である。

### キーワードグループと .kwd 交換

- 旧開発版の単一グループ設定は、そのままグループ1として読み込む。開いただけで設定を
  書き換えず、グループ2〜10の既定値を補う。グループ切替は下書きを保持し、確定時は
  各グループの変更フィールドだけをマージする。キャンセルは全グループの下書きを破棄する。
- 「カラー」へキーワード2〜10の項目を追加。ライト／ダーク別の独立した既定配色と、
  文字色・背景色・太字・下線・非表示に対応する。新しい既定色はMac版独自で、
  Windows版の色定義ファイルをそのまま取り込む機能ではない。
- `.kwd`の1行1語、先頭`//`のコメント、`// CASE=True`／`// CASE=False`に対応する。
  CASEがない場合は選択グループの設定を維持し、複数指定なら最後を使う。
  UTF-8、UTF-16LE/BE、CP932、EUC-JP、ISO-2022-JPを読める。自動判定が曖昧な場合は
  ファイル選択パネルで文字コードを明示する。取込み上限は256KiB。
- 本家が許容する全キーワード形式ではなく、現在の単語文字・長さ・総数制限に合う範囲のみ。
  未対応文字や空白を含む語、不正なCASE、変換エラー、上限超過はファイル全体を拒否し、
  行番号等を表示する。未対応語を黙って省略しない。完全に同じ語の重複だけを除く。
  本家形式の確認元はローカルの`sakura_core/typeprop/CImpExpManager.cpp`の
  `CImpExpKeyWord::Import/Export`。配布済みの第三者キーワード素材は新たに同梱しない。
- 読込みは選択グループの単語と大小文字の下書きだけを置き換え、正規表現・他グループ・
  保存済み設定は保持する。適用／OKまでは確定せず、キャンセルで破棄できる。
  書出しは選択グループの単語とCASEだけをUTF-8 BOM＋CRLFで保存する。
  正規表現・配色・他グループは`.kwd`には含めない。保存先は都度ユーザーが選ぶ。

### 選択範囲検索・共有履歴・一致件数

- 検索パネルの「選択範囲内」は通常選択をペイン固有の固定範囲として保持する。
  検索結果の選択移動では範囲を変えず、「範囲を再指定」で取り直す。矩形範囲は未対応。
  単一／全置換では置換後の長さへ範囲を更新し、範囲外の本文を変更しない。
  手編集、別ペインの変更、Undo／Redo後は古い範囲を無効化し、再指定を要求する。
  古い範囲を黙って文書全体へ切り替えることはない。範囲指定の解除は明示操作で行う。
- リテラル／正規表現、Unicode単語検索、前後検索、零幅一致に範囲を適用する。
  正規表現の完全一致部分は範囲内へ制限し、先読み・後読みと単語境界は元の本文を参照する。
  範囲の端を新しい文書先頭／末尾として扱わない。ICUの`setRegionAndStart`、
  transparent bounds、非anchoring boundsを使用する
  （[ICU正規表現API](https://unicode-org.github.io/icu-docs/apidoc/released/icu4c/uregex_8h.html)）。
  「折返し検索」をOFFにすると前後検索とも端で停止し、零幅一致の末尾でも繰り返さない。
- 検索文字列、置換文字列、大小文字、単語、正規表現、折返しを開いている文書間で共有する。
  範囲指定は共有しない。検索文字列は4,096、置換文字列は65,536 UTF-16単位まで。
  実行済みの検索／置換履歴はそれぞれ最大20件の重複なしMRUで、履歴1件は4,096単位まで。
  起動中のメモリだけに保持し、UserDefaults、ファイル、システム検索ペーストボードへは保存しない。
  「履歴を消去」は全パネルの履歴と現在の検索／置換文字列を消し、検索フラグは維持する。
  通常のmacOS復旧バックアップ等とは独立した保持方針である。
- ⌘Eは通常選択をリテラルの検索文字列として共有する。本文やUndo履歴は変更しない。
  ツールバー検索にも現在の検索フラグを適用する。
- 「一致件数」は固定本文をバックグラウンドで数え、本文・選択位置を変更しない。
  4Mi UTF-16単位／100,000論理行／100,000一致を上限とし、ICUの1回250ms、
  処理全体2秒を目安に中止判定する。ハードリアルタイム保証ではない。
  本文、条件、範囲が変わったら進行中の処理を中止し、古い結果を表示しない。
- 強調表示は先頭10,000一致まで。逆方向検索は候補だけを保持する方式へ変更し、
  一致配列による100,000件の制限は廃止した。時間・キャプチャ等の上限は継続する。
  キャプチャ保持は1,048,576スロット、全置換は1,000,000一致を上限とし、超過時は編集前に拒否する。
  強調・件数・逆方向の範囲取得と、参照展開のない全置換は不要なキャプチャを保持しない。
  UIの単一置換展開は64Mi、全置換の展開総量と最終文書は128Mi UTF-16単位まで。
  全置換は途中失敗時に部分反映せず、成功時は1回のUndoで戻る。

### 保存・復旧の耐障害性（2026-10-25 ローカル実装）

- 復旧ファイルは0600の同一フォルダー内一時ファイルへ書き、`F_FULLFSYNC`、原子的rename、
  フォルダーの`fsync`、置換後の`F_FULLFSYNC`の順で同期する。新設した復旧フォルダーの
  親ディレクトリにも`fsync`を行う。未対応FSや同期失敗を黙って成功へ読み替えない。
- 通常保存はNSDocumentの安全な保存経路を維持する。途中の一時ファイルだけでなく、
  最終保存先の同期完了後に保存snapshotを確定する。同期失敗ではdirtyと復旧データを保持する。
  「書き出し」（NSSaveToOperation）は成功しても元文書を保存済みと扱わない。
- rename後の同期エラーは「変更反映済みの可能性があるが同期未完了」と区別する。
  Grep置換も同じ境界を区別し、変更件数へ含め、以降のファイルの保存を止める。
  作成したバックアップは残す。バックアップをOFFにした場合は復元用コピーは作られない。
- `.sakura-recovery.lock`を削除しない固定inodeの`flock`で排他する。
  協調するプロセス間で容量計測、世代回転、最新保存、過去世代の整理と明示削除を直列化する。
  競合時は待ち続けず保存を中止し、既存データを保持する。非協調の外部プログラムは制御できない。
- 共通設定「復旧」は過去0〜20世代、容量16〜4,096MiB。最新は常に保持し、既定は2世代／256MiB。
  各ファイルは256MiBまで。次回のバックアップから反映する。世代数を減らしたときは、
  有効な最新世代を正常に保存し終えた後、その文書の超過世代だけを削除する。
  破損した最新を修復する最初の保存では、有効な古いfallbackを整理せず保持する。
  容量を減らして超過した場合は自動削除せず保存を止める。ロックと中断時の一時ファイルも容量へ算入する。
- 全世代を同時にメモリへ読み込まず、回転元は1世代ずつ検証・保存する。
  シンボリックリンク、特殊ファイル、復旧名を装ったフォルダーを再帰削除しない。
  クラッシュで残った未知の一時ファイルを自動削除することはない。
- 自動試験はファイル同期／rename／フォルダー同期／最終同期への失敗注入、
  rename前後の子プロセス強制終了、プロセス間ロック、容量競合、0／5世代、
  設定検証、破損fallback、通常保存／安全保存／書き出しの状態保持を含む。
  プロセス終了試験は物理的な電源断や故障したストレージの試験ではなく、無条件の永続化保証ではない。

### 本文共有・検索強調の非同期化（2026-10-25 ローカル実装）

- `TextBuffer`を不変の論理行payloadと永続AVLノードへ変更した。
  新しいコピーはrootの共有だけで取得し、独立したコピーの読取りと元文書の編集を並行できる。
  同じ`TextBuffer`インスタンスそのものを複数スレッドから読み書きするAPIではない。
  改行を含む編集では近傍行だけを再解析し、不変の前後部分をsplit／joinする。
  編集する文字・行、解放する旧ノードの量に加えて、平衡木の経路更新が必要になる。
- `line(index)`はO(log N)で、全行走査は`lineCursor()`でO(N)とする。
  cursorは元のrootを保持するので、走査中に元bufferが変更・破棄されても無効にならない。
  レイアウト・表示行のoffset構築・sliceはこのカーソルを使う。
  複数箇所編集とUndo／Redo用の候補bufferも全文コピーせず取得でき、失敗時の原子性を維持する。
- 検索強調の要求は描画中に正規表現を実行せず、150msの休止後にバックグラウンドで処理する。
  本文・条件・範囲・IME／表示状態が変わった場合は古い結果を適用しない。
  現在の選択や本文を変更せず、可視行の装飾だけを結果到着後に更新する。
  10,000件、検索文字列4,096 UTF-16単位、ICUの1回250ms、全体2秒目安の制限を持つ。
  不正な式・上限・中止の状態をステータスバーへ表示し、部分的な失敗結果を適用しない。
  時間制限はハードリアルタイム保証ではない。通常の次／前検索も下記の非同期方式へ変更した。
- 件数確認と追加キーワード色分けもroot共有の固定本文を使う。
  件数確認の正規表現検証と本文の連結はworker側へ移し、完了時には実際の条件を再照合する。
  検索用の本文連結は行単位・長い1行の64Ki UTF-16区間で中止判定する。
- 通常のIME一時bufferは元本文の固定コピーへ局所置換し、組版と色分けで共有する。
  IMEからサロゲート／CRLFの途中を指す一時範囲が渡された場合は、従来の全文preview構築へ
  フォールバックして表示互換を維持する。本文・Undo・他ペインは変更しない。
  後述の索引レイアウト・共有NSStringにより通常表示の全文コピーと通常編集の全文組版は除去した。
  通常の構文解析は後述のworker・差分token索引へ分離した。復旧保存・削除も後述のworkerへ分離したが、復旧の起動時読込み、
  フォント／折返し幅変更時の全文組版はまだ残る。
- 不変payloadの共有、12,000回の構造編集、保持した過去本文、AVLの高さ・長さ・行数、
  読取り4スレッドと編集の並行動作、cursorとmove後の有効性、中止時の状態保持を試験する。
  UI試験は非同期要求、実行スレッド、条件の通知なし変更、IME、regex timeout、件数上限と
  preview共有／互換fallbackを含む。ThreadSanitizerとASan／UBSanも併用するが、形式的な証明ではない。
- 現状は1行ごとにノードとpayloadを持つため、短い行の多い文書では従来のvectorより
  メモリを多く使う。大規模文書の全操作要件を達成したという判定はしていない。

### 前後検索の非同期化（2026-10-25 ローカル実装）

- 次／前検索は検索式の検証・本文連結・一致走査をworkerで実行する。
  mainでは固定root、条件、選択位置の世代だけを記録し、本文の全文コピーや正規表現を実行しない。
  連続した次／前操作はFIFOで処理し、先行検索が見つからない場合も後続の方向操作を維持する。
  零幅一致の進行・サロゲート／CRLF境界・範囲内折返しも各結果の適用後に判断する。
  パネルを表示していない場合も、処理中・完了・中止・エラーを文書のステータスバーへ表示する。
- 本文、条件、範囲、手動選択、IME入力で待機中の要求も取り消す。
  完了時には実際の条件・本文revision・選択世代・範囲を再照合し、途中で変更して同じ位置へ
  戻った場合も古い結果を適用しない。検索は本文・Undo・dirty状態を書き換えない。
  同一条件の共有履歴通知は履歴だけを更新し、別文書で同時に進んでいる検索を止めない。
- 「検索中止」ボタン、検索メニューの「検索処理を中止」（⌘.）で前後検索・件数・強調を中止する。
  本文上のEscapeは進行中の前後検索／件数確認も中止し、検索パネルを閉じても処理を取り消す。
  本文編集や手動の選択移動も要求を取り消すので、遅れてカーソル位置を戻すことはない。
- 逆方向は全一致を配列にためず、直前候補または折返し先候補を保持する。
  100,000件の一致数上限は廃止し、100,005一致を含む試験でも最後の候補を取得する。
  これは本文連結を含めた全メモリがO(1)という意味ではない。文字列の連結・走査はまだ毎要求行う。
  必要なキャプチャは走査中の正しいICU状態から取得し、`\G`を含む選択肢を新たな開始位置で
  再評価しない。キャプチャ上限は保持候補に適用し、破棄した全候補の合計にはしない。
- ICUの1回250ms、全体5秒目安で中止判定し、中止・式の誤り・資源エラーでは選択を変更しない。
  時間はハードリアルタイム保証ではない。前後検索中の単一置換は実行せず、検索完了後の再操作を案内する。
  全置換は先行する前後検索を取り消し、後述の非同期準備・一括反映を使う。
  単一置換の対象確認・展開・編集も、後述の共通準備queueへ移した。
- 新しいcore試験は全一致を使う参照選択、無作為入力、Unicode、範囲、零幅、キャプチャ、
  `\G`、中止、10万件超を含む。UI試験は連続方向操作、260件の零幅停止要求、
  手動移動・編集・IME・通知なし条件変更、同時文書、明示中止、パネル終了通知を含む。
  UIオブジェクトは画面を表示せず試験し、ASan／UBSanとThreadSanitizerでも確認する。

### 全置換の非同期準備とsnapshot Undo（2026-10-25 ローカル実装）

- `EditEngine::Snapshot`は共有本文、editor固有の所有者token、状態IDを保持する。
  workerはこの固定本文だけから`PreparedEdit`を準備し、liveのeditorや文書を読まない。
  `commitPrepared`は所有者、状態ID、本文root、revisionがすべて同じ場合だけ一度だけ受理する。
  手編集→Undoで同じ本文へ戻った場合、同内容の再読込、他editorへの流用も拒否する。
  保存文字コードなどのmetadataは候補本文へ含めず、現在の文書設定を維持する。
- 元本文の非重複・昇順の置換範囲を、近接する論理行ごとにまとめて組み立てる。
  長大な1行の10万箇所を1件ずつ全文再コピーしない。離れたgroupは後方から適用し、
  未変更の本文部分木を共有する。範囲、Unicode／CRLF境界、出力容量を検証してから公開する。
  検索、置換展開、本文のcopy／再構築、組版には中止判定を持つ。
  メモリ確保や1個の巨大書記素の処理までハードリアルタイムで中断する保証ではない。
- Undo／Redoは変更前後の不変rootを保持する履歴へ変更した。各actionは1回で戻せる。
  rootの復元でもlive revisionは進め、古い非同期要求を有効に戻さない。
  既存の順次batch編集のrevision進行数と、保存状態IDの対応を維持する。
  長い履歴chainは再帰destructorでなく反復して解放する。
  caller所有の`TextBuffer`へeditorを通さない書込みがあれば、Undo／Redoや準備結果で
  その内容を消さず、明示的な`clearHistory`まで新しい編集・履歴の適用を拒否する。
- AppKitの全置換はserial worker queueを使い、検索式の検証、全一致、展開、候補本文、
  Undo情報に加えて、文書を表示する各ペインの表示行索引を準備する。
  mainで取得するのは固定rootと文字コードに依存しない検索／画面設定である。
  Core Textのfontとlayout objectsは各worker内で作成・使用し、AppKit viewやNSFontをworkerで操作しない。
  この分離は[AppleのCore Text threading contract](https://developer.apple.com/documentation/CoreText)に従う。
- mainの反映直前にも本文、検索／置換条件、固定範囲、手動選択の世代、IME状態、
  ペイン構成とfont／TAB／折返し幅を再照合する。通知なしの条件変更でも古い結果を適用しない。
  他ペインの未確定入力も保護し、入力中なら開始せず、準備中に入力が始まれば中止する。
  同じ条件の共有履歴通知は他文書の処理を取り消さない。
- 変更があれば本文と対応する各ペインの準備済み索引を反映する。
  古いredo履歴・索引はworker所有の結果へ移し、main callback終了時に大量解放しない。
  自動scrollbar切替などで反映後にviewportが変われば従来の再組版経路が必要になるため、
  すべての表示変更が非同期になったとは扱わない。
  通常の単一編集によるredo破棄や`clearHistory`の大量解放も、今後の最適化対象である。
  この段階では大規模なUndo／Redo後の再組版や、bookmarkの全文比較・位置再配置もmainへ残っていた。
  Undo／Redoの組版準備は後述の非同期履歴経路へ置き換えた。
- 中止ボタン、⌘.、Escape、検索パネル終了、本文・条件・手動選択・IME変更、別の検索操作で中止する。
  新たな全置換は前の要求を取り消す。中止／競合／資源エラーではlive本文・Undoを変更しない。
  すでに反映した操作を中止で自動的に戻すものではなく、反映後はUndoを使う。
  同じ文字列への置換は件数を示すが、dirty・revision・redoを変更しない。
  置換で固定範囲端が新しいCRLF／サロゲート結合の内部になれば、範囲を無効にして再指定を求める。
- 全置換の上限は1,000,000一致、置換文字合計と最終本文128Mi UTF-16単位、既存のcapture上限、
  ICUの1回250ms、準備全体5秒目安である。時間はqueue待ちを除き、ハードリアルタイム保証ではない。
  同期のコアAPIも残し、Grep worker等は同じ準備・commit経路を使う。
  単一置換も後述の共通準備経路を使う。bookmark補正の全文コピーは後述の共有本文比較へ置き換えたが、
  補正の最悪時比較や明示保存の符号化等は別の残件である。
- コア試験は無作為2,000 batchの素朴な文字列組立てとの比較、CRLF／サロゲート結合、
  10万箇所の長い1行、全中止checkpoint、4万履歴の解放、保存token、異なる所有者、
  直接書込み、worker準備とlive編集の並行実行を含む。
  UI試験は一括Undo／Redo、no-op、中止、条件通知なし変更、手動移動、edit→Undo、再読込、
  IME、2ペインのCore Text結果照合、scope、lookaround/capture、零幅、式エラー／timeout、
  同時文書、非表示パネルでのstatusを含む。全既存操作や実機入力の完全性の証明ではない。

### 差分レイアウトと共有表示文字列（2026-10-25 ローカル実装）

- `TextBuffer::changesFrom`は旧・新rootの共通部分木を飛ばし、変更を囲む論理行区間と
  UTF-16範囲を返す。CRLFの結合、行挿入／削除、Undo／Redo、別snapshotにも使える。
  同じrootは1比較で一致する。複数の離れた編集をまとめた場合は、その間も含む1区間になる。
- `IndexedLayout`は最大64論理行のblockを持つ永続AVL索引である。
  各部分木に論理行数、表示行数、UTF-16長、最大幅を集約する。
  通常の1行編集はその行、改行編集は本文側で再構築した近傍行だけを再計測し、
  古い区間をsplit／joinで差し替える。後続行の絶対offsetや行番号を全件書き直さない。
  短い隣接blockは結合し、編集を繰り返しても1行1ノードへ断片化することを抑える。
- 折返しのない行は追加のfragment配列を持たない。折返しの継続fragmentだけを共有配列へ保存し、
  近傍blockの分割・結合時に長大な未変更行のfragmentをコピー・再走査しない。
  任意表示行の取得、本文offsetからの表示行取得、最大幅取得に全文表の構築は不要である。
  offsetの検索は本文・表示の索引をそれぞれ辿り、`lineLookupSteps`は表示索引の訪問ノード数を記録する。
  改行コード内部は前の表示行、折返し境界は従来どおり前のfragmentへ所属する。
- フォント、サイズ、文字間隔、TAB幅、折返し方式／幅が変われば全体を再計測する。
  任意metrics実装では`metricsRevision`の更新が必要で、メトリクスの変化を無条件に推測するAPIではない。
  長大な単一行を変更した場合も、その論理行全体の再計測は必要である。
  各更新は計測・確保がすべて成功してから公開し、失敗時は旧索引を保持する。
  コピー／move後の索引は固定rootを共有し、編集前の行位置を独立に問い合わせられる。
- `SakuraBufferString`は[NSStringの公開subclass契約](https://developer.apple.com/documentation/foundation/nsstring?language=objc)に従い、
  固定本文を保存域にして`length`、`characterAtIndex:`、`getCharacters:range:`を実装する。
  通常表示文字列の作成とimmutable copyで全文を連結しない。
  描画は要求された表示行だけをnative NSStringへ切り出す。
  全文のUTF-8化、mutableCopy、全文比較などを利用側が明示要求すれば、その処理量は全文に比例する。
- IMEの表示文字列は固定本文のprefix／未確定文字／suffixを重ねる。
  サロゲートやCRLFの途中を指す一時範囲も、生のUTF-16として保持し、本文・Undoを変更しない。
  正常な編集境界の組版は共有本文の一時bufferへ局所置換し、通常表示と同じ索引で更新する。
  不完全境界の組版だけは互換用の全文buffer構築を残す。
  非同期追加色分けのIMEキーは本文そのものの比較でなく、保持したcomposition identityで照合する。
- コア試験は無作為4,500編集で全文レイアウトとの全表示行・幅・offset・位置検索を比較する。
  64,000行で150回の1行編集が各1行だけを計測すること、構造編集、最大幅、metrics変更、
  失敗時の旧状態保持、block分割・結合・AVL集約、保持した旧索引の並行4読取りも確認する。
  UI試験は通常編集・改行編集・IMEで計測行数と全体再計測回数を調べ、従来の描画／TAB／
  書記素／矩形選択／候補位置試験も維持する。NSStringはnative文字列、CFStringとの相互操作、
  不完全UTF-16範囲、mutableCopy、UTF-8化、並行6読取りを確認する。
  これらは全てのAppKit利用経路、全入力メソッド、Intel実機での検証を意味しない。

### 通常色分けの非同期処理（2026-10-25 ローカル実装）

- 通常の言語字句解析も75ms debounce後にserial workerで行う。描画中に全文連結や
  全文lexerを呼ばない。未知拡張子で追加ルールもなければworkerを開始しない。
  取得するのは共有rootの固定本文で、IME中は組版が保持するpreviewのrootを使う。

- 本文連結、文字走査、区切り検索、長いコメント／文字列、HTML内のJS/CSSにも中止判定を持つ。

### 差分字句解析とトークン索引（2026-10-25 ローカル実装）

- `IndexedSyntax`は全22言語＋plainについて、通常lexerの外側の論理行境界に
  約4Ki UTF-16単位ごとのcheckpointを作る。複数行tokenの途中では切らない。
  行頭状態、HTML/XMLのtag／name／closing／script・style待機状態を保持する。
  任意の行を無条件に通常状態から再開したり、色付きtokenだけで状態を推測したりしない。
- 入力参照の最遠位置もblockごとに記録する。閉じ記号が見つからなかった先読み、
  Markdownの後方のdelimiter、HTMLの埋込み言語等も依存へ含める。
  `TextBuffer::changesFrom`の変更区間へ依存する最も早いblockまで戻り、
  未変更suffixのcheckpointで状態が一致したときだけ既存結果を再利用する。
- 初回は全文、更新は原則64Ki UTF-16単位以上の入力windowを取得する。
  lexerには実際の残り全文長を渡す。windowを超える参照は入力拡張要求となり、
  windowを倍増して再試行する。window末尾をEOFや閉じ記号として誤認しない。
  失敗・中止した試行のblockは公開せず、以前のindexを保つ。
- blockはtoken位置を相対値で保持し、文字数・件数・先読み依存を集計する共有AVL木へ格納する。
  前方への挿入でも後続tokenの位置配列を書き換えない。独立したindexのコピーは不変nodeを共有する。

### 保存設定の世代保護と復旧保存の非同期化（2026-10-25 ローカル実装）

- `markSaved`が古い保存snapshotの文字コード／BOMで現在の設定を上書きする不具合を、
  新しい回帰試験で10件の期待値不一致として再現してから修正した。
  本文の状態ID・全metadataの世代とは別に出力文字コードの世代をtokenへ保持する。
  明示的な文字コード変更がなければ成功した保存のBOM方針を反映し、変更があれば新しい設定を保持する。
  文字コードを変更して元の値へ戻した場合も、値の比較だけで古いBOM方針を適用しない。
  改行等の別metadata変更はBOM方針の反映を妨げず、未保存metadata自体はdirtyのまま残す。
- `SakuraRecoveryWriter`はmainで共有本文snapshotと小さいmetadataを取得する。
  本文のNSString化、binary plist符号化、世代回転、同期書込み、削除、旧snapshot解放をutility側で行う。
  各文書の待機分は最新writeへまとめ、削除要求は古い待機writeを無効にしたうえで保持する。
  待機キューは削除と最新writeの最大2操作。処理中のwriteは後続writeだけでは破棄せず、
  開始済みsnapshotを新しい要求だけを理由に延期しない。編集後2秒のidle timer自体は従来どおりで、
  途切れない入力中にも定期保存する保証ではない。複数文書のI/Oも同じ直列queueを使う。
- 保存・正常再読込・closeはepochを進めて削除を要求する。既にdurable I/Oへ入った旧writeは
  完了してもよいが、その後に削除を実行し、新しいwriteはさらに後へ並べる。
  保存後に新しい編集があれば従来どおり復旧を再予約する。失敗した再読込は旧writeを無効にしない。
  close後の遅れた予約は無視し、workerはdocument／writer本体の寿命に依存せず完了できる。
  古い成功／エラー通知は新しい要求の状態を変更しない。最新の失敗はmainへ返し、dirtyと既存バックアップを保持する。
- 終了は`NSTerminateLater`を使う。[Appleの`terminate:`仕様](https://developer.apple.com/documentation/appkit/nsapplication/terminate(_:))に従い、
  NSApplicationが先に行う文書の保存／破棄／取消し確認を維持する。delegate到達時の確認済み文書は
  再度確認せずcloseし、復旧groupの完了を非同期で待つ。終了待ち中の新文書だけは
  `NSDocumentController::closeAllDocumentsWithDelegate:`へ再確認を委譲する。
  待機中に新文書が開かれた場合は、その文書も確認してから終了する。取消し後の再試行、重複終了要求も扱う。
  起動時の「すべて破棄」も同じ非同期削除を使う。終了待ちはmainをブロックせず、未完了I/Oを時間切れで捨てない。
  main通知はcommon-mode run-loop blockを使い、main GCDの中から入った終了待ちのmodal loopでも完了できるようにする。
- 削除は成功を返すchecked APIを追加した。存在しない復旧directoryは成功とし、busy lock、
  非通常ファイル、unlink／削除後の同期失敗はエラーにする。保存済み本文は巻き戻さず、
  終了済み文書ではログへ通知する。旧世代整理の失敗も黙って成功にしない。
  本文だけで容量上限を超える場合はbinary plist生成前に拒否し、正確な容量検査も従来どおり行う。
- 新規`RecoveryWriterTests`は、停止点を持つ隔離I/OでUnicode snapshotの固定、100連続要求のまとめ、
  active write→remove→new writeの順序、close後の復活防止、所有者解放後の完了、I/O失敗とC++例外、
  古い通知の拒否、main timerの進行、終了取消し・再試行・終了待ち中の新文書、modal modeとmain GCD内の入れ子待ちを検査する。
  実際の`SakuraDocument`でも保存・再読込成功／失敗・closeとの重なり、エラー後の再試行と既存backup保持を確認する。
  AppKitの実際の保存確認ダイアログ操作や物理電源断の試験を代替するものではない。
- 最終のmodal対応コードでDebug／Universal Release／ASan＋UBSanは各37/37成功した。
  TSanは`PortableCoreTests`、`RecoveryStoreTests`、`RecoveryWriterTests`、`DurableFileTests`、
  `FileWorkflowTests`の関連5/5が成功した。Universalのarm64／x86_64 sliceを確認したが、
  テスト実行は開発ホストのarm64側であり、Intel実機動作・実際の保存確認操作・公開版更新を示すものではない。
- 明示保存の本文連結・符号化、起動時の復旧列挙／読込み／復元、外部変更監視は同期のままである。

### Undo／Redoの非同期準備と複数ペイン反映（2026-10-25 ローカル実装）

  旧本文・履歴・組版はplanに保持し、反映後のworkerで解放する。長い履歴chainの最終所有者が
  並行して解放される場合も、node destructorを含む反復解放で深い再帰を避ける。

### 日本語文字コードの自動判定と曖昧性（2026-10-25 ローカル実装）

- 文字コードの明示指定とUnicode BOMの既存優先関係を維持する。

  不正なBOM本文をレガシー形式へ読み替えたり、未変換バイトを置換文字で埋めたりしない。
- 本家の`CESI::GuessEucOrSjis`と`codechecker.h`を参照した改変移植である。

  明示指定、BOM、ASCII／ISO切替、70KiB超、無作為4,000入力、並行6読取りを含む。
  文書の警告表示・再読込、Grepの混在候補全体の実行拒否／明示後の保存、
  `.kwd`拒否／明示後の取込み、復旧の警告記録と不正型拒否も回帰確認する。
  用途別本文は権利の明確な自作例であり、実ユーザーの既存文書や独立した正答率評価ではない。
  漢字のみ・極短文・意図的な半角カナ・混合文字コード、BOMなしUTF-16等の追加評価は残る。

## 既知の未実装

- 日本語文字コード推定の多様な実在文書による精度評価、BOMなしUTF-16などの追加推定。
  CP932／EUC-JPのバイト比較と推定警告は実装したが、全入力の正解や本家の全判定設定との互換は未達
- ICUと本家Bregonig／Onigmoの正規表現構文・オプションの完全互換
- 禁則、言語別の詳細な色分け
- Windows版Grepの絶対パス／引用符付き除外指定などの完全互換
- タイプ別設定の残りの詳細項目（TSV、禁則、背景画像、IMEなど）、共通設定の各詳細項目
- 複数選択、3ペイン以上の分割とペインの同期スクロール
- 外部ファイルの移動先追跡、差分比較、実際の電源断を含めた耐障害検証
  （現状はパス消失を削除・移動として扱うポーリング監視）
- Windows設定・テーマ・マクロ・プラグイン互換
- VoiceOver向け本文・選択範囲の完全なアクセシビリティ表現
- Developer ID署名、Hardened Runtime、公証

Grep置換の保存は同一フォルダーの一時ファイルと原子的renameを使い、
ファイルロックと複数回の内容・実体照合で競合を検出する。ただしロックに従わない
外部プログラムが最後の照合とrenameの間に書き込む競合を完全には排除できない。
中止は以降の保存を止めるもので、すでに保存したファイルを一括ロールバックしない。

現在の`TextBuffer`と表示行は共有ツリーで、表示NSStringも固定本文を参照する。
通常編集／IMEの組版と字句解析は変更周辺を中心に更新し、文書検索は小さい窓で全文へアクセスする。
明示保存の全文連結・符号化、復旧の起動時読込み、フォント／幅変更時の全文再組版は残る。
長大文書の全操作・全描画・実際の入力メソッドを通した性能要件を達成したという判定はしていない。
拡張書記素の境界は[ICUの`\X`](https://unicode-org.github.io/icu/userguide/strings/regexp.html)
で認識する。標準SDKの公開C APIを使い、追加のHomebrew ICUには依存しない。
ASCIIのみの行はmatcher生成・cluster計測を省く。非ASCIIを含む単一論理行の長さは
ICUのint32 UTF-16範囲までで、使用中のICU／OSによるUnicode版の差は残る。
Core Text計測のcluster cacheは4,096種類・各64コード単位まで、巨大clusterは保持しない。
任意の比例フォントやArabic等の文脈依存組版、太字など異なる装飾フォントを跨ぐ字幅、
禁則、双方向テキストを含めたWindows版との完全な組版互換は未達。

### Grep除外フォルダーの指定

`;`、`,`、改行で複数指定する。単名（例 `node_modules`）はすべての階層の
フォルダー名に一致し、パス（例 `vendor/generated*`）は検索rootからの相対パスに
限定する。大小文字は区別せず、`*`／`?`は最後の名前だけに使える。内部の空白は
名前の一部として扱う。空欄は従来の検索条件を維持する。

絶対パス、`~`、`.`／`..`、空の階層、途中階層のwildcard、引用符等は実行前エラーに
する。本家のすべての除外構文に対応したものではない。隠しファイル・package・symlinkを
たどらない方針とバックアップ除外は従来どおりで、検索root自体や祖先名は除外しない。

## 任意実行の性能測定

通常のCTestへ巨大入力は含めない。性能測定用targetは明示的に有効にする。

```sh
cmake -S . -B build/macos-default -DSAKURA_BUILD_BENCHMARKS=ON
cmake --build build/macos-default --parallel
build/macos-default/tests/performance/sakura_core_performance
build/macos-default/tests/performance/sakura_core_performance --core-text
build/macos-default/tests/mac/sakura_editorrendering_tests --benchmark
build/macos-default/tests/mac/sakura_asyncnavigation_tests --benchmark-large-search
build/macos-default/tests/portable/sakura_IndexedLayout_tests --benchmark
build/macos-default/tests/mac/sakura_editorrendering_tests --benchmark-layout-edit
build/macos-default/tests/portable/sakura_PreparedEdit_tests --benchmark
build/macos-default/tests/mac/sakura_asyncreplacement_tests --benchmark-large-replace
build/macos-default/tests/mac/sakura_asyncreplacement_tests --benchmark-large-single
build/macos-default/tests/mac/sakura_asyncsyntax_tests --benchmark
build/macos-default/tests/mac/sakura_asynchistory_tests --benchmark-large-history 32
```

コア計測はASCIIのUTF-8入力100MiB・1,000,000論理行、80字相当の折返しで
2,000,000表示行を生成し、ロード・全行レイアウト・100,000回の位置検索を個別に測る。
入力サイズ、行数、各検索結果の照合も行う。2026-10-24の前段階（行offset配列版）、
Debugビルド・各1回の参考値：

| 計測 | 固定幅metrics | Core Text metrics |
| --- | ---: | ---: |
| UTF-8ロード | 1,483.783 ms | 1,516.809 ms |
| 全行レイアウト | 2,003.752 ms | 2,539.457 ms |
| 100,000回の位置検索 | 63.442 ms | 60.830 ms |

一部の通常テストと実行時間が重なっており、統計的な比較や改善率を示す値ではない。
同日のFenwick索引版・Core Text・同じ入力での追加参考計測では、ロード1,614.151ms、
全行レイアウト2,495.830ms、100,000回の位置検索71.297msだった。
`--edits 100`（既定値）は前方／末尾で挿入と削除を100回ずつ実行する。
各200操作の時間は前方1.021ms、末尾1.469ms、最後の一組のUndo＋Redoはそれぞれ
0.003ms／0.002ms。時間にはlength、行数、末尾行offset、挿入位置と本文の検査も含む。
変更前の編集時間は測定していないので、改善率を示す数値ではない。
拡張書記素対応を加えた段階の2回ではロード1,562.814／1,971.957ms、全行レイアウト
3,134.494／3,633.293ms、位置検索144.857／120.630ms、前方200編集1.060／0.989ms、
末尾200編集1.459／1.421msだった。その後、ASCIIループ内の文字列への重複アクセスを
減らした最終コードの1回は、ロード1,517.087ms、全行レイアウト1,083.298ms、
位置検索66.824ms、前方200編集1.004ms、末尾200編集1.448msだった。
いずれもサイズ・行数・検索位置・編集結果の照合に成功。測定回数が少なく、実行間の
ばらつきや同条件の対照測定を十分評価していないため、速度改善率の根拠にはしない。
このコア計測はAppKit描画・IME・ファイルI/O・外部監視・復旧保存を含まない。
別のAppKit object計測は`x\n`を100万回並べた2,000,000 UTF-16コード単位の入力
（末尾空行を含め1,000,001論理行）で、初回の解析・可視描画とwarm再描画を分ける。
前段階のDebugビルド・1回の参考計測は文書構築／レイアウト418.806ms、初回可視描画
312.799ms、warm100回の再描画34.949ms（平均0.349ms／回）、末尾256位置の照会
25.923msだった。1再描画8表示行で、warm時は本文・表示行・構文・検索・装飾の
構築カウンタが増えないこと、位置照会の比較回数が対数オーダーの上限内であることも検査する。
これは100MiB文書のUI操作計測ではなく、実ウィンドウでの操作感も検証しない。
100MB／100万行の全操作要件を達成したという判定はしていない。

2026-10-25の共有AVL／cursor版、Universal ReleaseをApple Siliconで実行した1回の参考値：
固定metrics、100MiB／1,000,000論理行／2,000,000表示行でロード318.987ms、
全行レイアウト216.611ms、100,000位置検索92.898msだった。
固定本文10,000コピーの取得は0.043ms、前方／末尾の各200文字編集は0.285／0.311ms、
各200回の改行挿入・削除は0.725／0.640ms。構造編集の最後のUndo＋Redoは0.005／0.004ms。
全編集後の本文と保持した固定本文を全文照合し、行数・長さ・AVL不変条件も検査している。
`time -l`の最大RSSは983,007,232バイト（照合用の全文連結2個等を含むプロセス全体）で、
エディタの定常使用量の測定ではない。以前のDebug値との速度比やメモリ優劣は示さない。

同じ段階のAppKit object計測（2,000,000 UTF-16単位／1,000,001行）は、
構築／レイアウト117.142ms、最初の可視描画616.495ms、その後の検索強調待ちと再描画12.488ms、
warm100描画35.859ms、末尾256位置照会22.737ms、最大RSS300,253,184バイトだった。
最初の描画は強調workerの完了待ちを含めず、その待ちを別区間に分離した。
これは実ウィンドウの100MiB入力・IME操作試験ではなく、初回の通常構文解析等による
mainスレッドの長時間処理も残っている。両計測とも他の負荷は厳密に統制していない。

前後検索の非同期段階で追加した`--benchmark-large-search`は、生成した100MiB／
1,000,000行の先頭・末尾へ`needle`を配置し、前方の先頭一致と逆方向折返しの末尾一致を確認する。
画面を表示しないAppKit objectで、描画・IMEを含めない。Release／Apple Siliconの1回では、
mainでの要求発行が前方0.156ms／逆方向0.120ms、結果適用まで48.377ms／102.549msだった。
main queueのheartbeatは最初の前方で47.242ms、後続の逆方向で0.258ms後に処理された。
全体の最大RSSは940,867,584バイト。測定区間、初期化、他の負荷を統計的に分離した値ではなく、
すべてのパターン・初回応答・実ウィンドウの低遅延やメモリ上限を保証しない。

同日の初期段階では通常Debug版とUniversal Release版で当時の8系統すべてのCTestが成功し、
コアのみのAddressSanitizer＋UndefinedBehaviorSanitizer構成でも全テストが成功した。
確保失敗の注入試験は未実施。Universal実行ファイルにarm64／x86_64両方が
含まれることを確認しているが、テスト実行は開発ホスト上であり、Intel Mac実機での
動作や、Windows本家との画像・挙動の完全一致を検証したものではない。

タイプ別画面設定のパネルは変更項目だけを保存し、既定へ戻した後も編集した項目だけ
タイプ値へ固定する。モデルの従来の全項目保存APIは互換性のため残している。
カラーの競合回帰は同一キー／別キー、確定順序の逆転、同値、リセット、外部書込み、
所有ウィンドウ終了を検証する。設定パネルの見た目や実IMEでの候補操作を含む、
人手による本家との完全一致試験は未実施。
