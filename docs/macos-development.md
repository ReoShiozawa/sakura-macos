# macOS 移植版の開発

このブランチは、本家とは独立した非公式改変・移植版である。
公式 `sakura-editor/sakura` の `b1eef8a` を基準に、
基本設計書 `sakura_editor_macos_port_design.md` の M1〜M3 を段階的に実装する。

## 開発ビルド

Command Line Toolsだけでも、CMakeのUnix Makefilesで開発用AppKitアプリを生成できる。

```sh
cmake -S . -B build/macos -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/macos --parallel
ctest --test-dir build/macos --output-on-failure
open build/macos/ui/mac/SakuraEditor.app
```

ヘッドレスなコアだけをビルドする場合は次を使う。

```sh
cmake -S . -B build/macos-core \
  -DCMAKE_BUILD_TYPE=Debug \
  -DBUILD_TESTING=ON \
  -DSAKURA_BUILD_MAC_APP=OFF
cmake --build build/macos-core --parallel
ctest --test-dir build/macos-core --output-on-failure
```

arm64とx86_64を含むUniversal Binaryは次のように生成する。

```sh
cmake -S . -B build/macos-universal \
  -DCMAKE_BUILD_TYPE=Release \
  -DSAKURA_BUILD_UNIVERSAL=ON
cmake --build build/macos-universal --parallel
lipo -info \
  build/macos-universal/ui/mac/SakuraEditor.app/Contents/MacOS/SakuraEditor
```

Developer ID署名・公証による外部配布は未完了である。
公開準備・権利確認・配布前の手順は[RELEASING.md](RELEASING.md)を参照。
正規表現はmacOS SDKの`libicucore`を使う。他OSでポータブルコアをビルドする場合は
ICUの`uc`・`i18n`開発ライブラリが必要で、Windows向けにはvcpkg依存を宣言している。

## 現在の実装範囲

- UTF-16 `char16_t`を使うポータブルな論理行バッファ
- CRLF、LF、CRの行単位保持
- UTF-16コード単位の位置変換と、CRLF・サロゲートペアの分断防止
- 挿入、削除、置換、Undo、Redo、保存時スナップショット
- 行の累積長をFenwick索引で管理し、普通の単一行文字編集は対象行の文字列処理と
  O(log N)の索引更新で処理。後続の全行offset更新や行vector全体の移動を避ける
- CRとLFが新たに結合する編集も正規化してUndo／Redoを維持。
  複数箇所の編集は全変更の成功後に確定し、後半で失敗しても本文・履歴を変更しない
- UTF-8、UTF-16LE、UTF-16BEの厳密な読込・保存とBOM維持
- macOSのCore Foundationを用いたCP932（Shift_JIS）、EUC-JP、ISO-2022-JPの読込・保存
- 読み込んだ文字コードとBOMを文書ごとに保持し、保存時に同じ形式を既定として再出力
- UTF-8、UTF-16LE／BE、CP932、EUC-JP、ISO-2022-JPの文字コード指定、
  BOM有無、入力改行コード（CRLF／LF／CR）を文書単位で変更する設定パネル
- 指定文字コードでの明示的な再読込。未保存の編集がある場合は破棄確認を表示
- `ITextMetrics`を境界にしたPortable LayoutEngine（折り返し、タブ、UTF-16境界）
- Core Textのフォント計測を`ITextMetrics`へ接続し、通常表示時の文書サイズ計算に利用
- 結合アクセント、和文濁点、国旗、肌色修飾、ZWJ絵文字などの拡張書記素を分断しない
  折返し。Core TextではUTF-16単位幅の加算ではなく、まとまり全体の幅を実測する。
  クリック位置も結合文字の途中へ入らないよう調整。通常表示とIME未確定表示に共通適用
- C/C++、Objective-C、Swift向けの軽量シンタックス色分け（コメント、文字列、予約語、数値、プリプロセッサ）
- 数値Function Codeを使う最小CommandBus
- UTF-16境界を守る検索・置換（リテラル、ICUのUnicode正規表現、
  単語単位、折返し検索）。日本語・絵文字への`.`、文書先頭アンカー、
  先読み、零幅一致、キャプチャ参照を含む逐次置換と全置換に対応
- `NSDocument`による複数文書、Finder/Openパネルからの読込・保存
- 2秒間隔の外部変更監視。未編集なら自動再読込し、編集中なら再読込／別名保存／
  現在内容保持を選択。削除・移動時は別名保存または現在内容保持を選択
- 編集後2秒のアイドル時に、本文、元パス、文字コード、BOM、入力改行コードを
  原子的なバイナリplistへ保存する復旧バックアップ
- 異常終了後の起動時に、未保存文書を復元／後で復元／すべて破棄できる復旧ダイアログ
- macOSのインプレース自動保存は使わず、明示保存と独自復旧バックアップを使用
- Core Text描画の独自`NSView`
- 折り返し表示に追従する行番号ガターと現在行の強調表示
- 同一文書を共有する2ペイン分割表示（ツール > ウィンドウ分割、カーソルとスクロールは独立）
- C/C++、Objective-C、Swift、Markdownの構造候補を一覧化し、選択行へ移動するアウトライン解析パネル
- 使用可能なメニュー操作とショートカットを列挙し、選択操作を実行するコマンド一覧パネル
- Windows版のタイプ一覧に合わせた「タイプ別設定一覧」と、6ページ構成のタイプ別設定パネル
- Windows版の設定分類に合わせた10ページ構成の共通設定パネル
- 共通設定からエディタのフォントサイズとTAB幅を永続化し、開いている全ペインへ即時反映
- タイプ別設定「スクリーン」「ウィンドウ」から、折返しなし／ウィンドウ幅／指定桁数、
  TAB幅、行番号表示、フォント書体・サイズ、行間、文字間隔を保存し、同じタイプの
  全ウィンドウ・分割ペインへ反映。適用、OK、キャンセルに対応

  フォントサイズ／TAB幅を共通設定から継承。Resetは下書きで、適用／OKで保存、
  Cancel／×で破棄する。通常の適用も変更項目だけを保存し、未編集の継承を維持
- Windows版の`ColorInfo_DEFAULT`に合わせた既定配色（暖色系本文背景、青い行番号と
  現在行下線、緑のコメント、青のキーワード、検索・選択色）
- 共通設定から「Windows クラシック」「macOSの外観に合わせる」「ダーク」を選択し、
  本文、ガター、選択、構文色、メニュー、ツールバー、ステータスバーへ即時反映

  古いCancelが他パネルのApply／OKを巻き戻さない。別キーの変更や未確定プレビューも

  選択行が消え、その後の色変更が無効になる経路を修正

  外部変更・パス差し替えは保存直前まで原文とメタデータを照合してスキップする。
  バックアップは保持した原文から作り、`.bak`・`.bak.N`を候補から除外する。
  候補保持は128MiBまでで、上限・検索中止・読込変換エラー時は置換実行を無効にする
- Grepの件数上限は検索結果の生成段階から適用し、正規表現評価の中止・時間制限と
  置換文字列展開量の上限を設ける。保存結果と競合・編集中・エラーをファイル別に表示する
- 本文文字列、表示行、構文解析、検索結果を変更依存でキャッシュし、文字装飾は可視行ごとに
  最大256行／8MiB目安のキャッシュへ保持。選択の変更は別の装飾として重ねる
- 再描画ではdirty rectangleに交差する表示行だけを走査。表示行の位置検索は二分探索を使い、
  ウィンドウサイズ計算でも全行のCore Text再計測を繰り返さない
- 通常文書・日本語文字コード・Grepファイル保存・エディタ選択移動・検索置換・
  Grep候補から実行・画面設定・描画キャッシュの8系統の自動テスト。
  設定適用／取消し、IME、色変更、TABと折返し、32,768行での探索回数も検証する。
  2,500回の固定seedランダム編集ではUTF-16文字列の単純実装と本文、全位置、行開始、
  行数、sliceを照合し、改行結合、copy／move、alias入力、失敗時の状態保持も検査する。
  AppKitテストは画面を表示せず、描画先はメモリ上のbitmap。本家との完全な等価試験ではない
- 公開準備のソース・バンドル検査、チェッカーの10件の正常系／拒否系試験、
  非公式版メニュー・About情報の画面非表示テスト。Pythonが利用可能な構成では
  機能テストと合わせてCTestの12系統となる。法的な権利監査・署名検証の代替ではない

Grep置換の保存は同一フォルダーの一時ファイルと原子的renameを使い、
ファイルロックと複数回の内容・実体照合で競合を検出する。ただしロックに従わない
外部プログラムが最後の照合とrenameの間に書き込む競合を完全には排除できない。
中止は以降の保存を止めるもので、すでに保存したファイルを一括ロールバックしない。

現在の`TextBuffer`は普通の単一行編集を対象行とO(log N)の索引更新で処理する。
改行を含む構造変更では近傍の論理行を再解析した後、行vectorの移動と全索引の再構築が
残る。複数箇所編集は原子性のため一時bufferへコピーするので、文書サイズ相当の
追加メモリを必要とする。本文編集後の表示行・構文・検索の全文再計算も残る。
IME未確定文字列は通常と同じ組版を使う一時bufferだが、その内容更新時の本文コピーと
全文レイアウトは未解消で、長大文書のIME操作性能の要件達成は未確認。
拡張書記素の境界は[ICUの`\X`](https://unicode-org.github.io/icu/userguide/strings/regexp.html)
で認識する。標準SDKの公開C APIを使い、追加のHomebrew ICUには依存しない。
ASCIIのみの行はmatcher生成・cluster計測を省く。非ASCIIを含む単一論理行の長さは
ICUのint32 UTF-16範囲までで、使用中のICU／OSによるUnicode版の差は残る。
Core Text計測のcluster cacheは4,096種類・各64コード単位まで、巨大clusterは保持しない。
任意の比例フォントやArabic等の文脈依存組版、太字など異なる装飾フォントを跨ぐ字幅、
禁則、双方向テキストを含めたWindows版との完全な組版互換は未達。

### Grep除外フォルダーの指定

`;`、`,`、改行で複数指定する。単名（例 `node_modules`）はすべての階層の
フォルダー名に一致し、パス（例 `vendor/generated*`）は検索rootからの相対パスに
限定する。大小文字は区別せず、`*`／`?`は最後の名前だけに使える。内部の空白は
名前の一部として扱う。空欄は従来の検索条件を維持する。

絶対パス、`~`、`.`／`..`、空の階層、途中階層のwildcard、引用符等は実行前エラーに
する。本家のすべての除外構文に対応したものではない。隠しファイル・package・symlinkを
たどらない方針とバックアップ除外は従来どおりで、検索root自体や祖先名は除外しない。

## 任意実行の性能測定

通常のCTestへ巨大入力は含めない。性能測定用targetは明示的に有効にする。

```sh
cmake -S . -B build/macos-default -DSAKURA_BUILD_BENCHMARKS=ON
cmake --build build/macos-default --parallel
build/macos-default/tests/performance/sakura_core_performance
build/macos-default/tests/performance/sakura_core_performance --core-text
build/macos-default/tests/mac/sakura_editorrendering_tests --benchmark
```

コア計測はASCIIのUTF-8入力100MiB・1,000,000論理行、80字相当の折返しで
2,000,000表示行を生成し、ロード・全行レイアウト・100,000回の位置検索を個別に測る。
入力サイズ、行数、各検索結果の照合も行う。2026-10-24の前段階（行offset配列版）、
Debugビルド・各1回の参考値：

| 計測 | 固定幅metrics | Core Text metrics |
| --- | ---: | ---: |
| UTF-8ロード | 1,483.783 ms | 1,516.809 ms |
| 全行レイアウト | 2,003.752 ms | 2,539.457 ms |
| 100,000回の位置検索 | 63.442 ms | 60.830 ms |

一部の通常テストと実行時間が重なっており、統計的な比較や改善率を示す値ではない。
同日のFenwick索引版・Core Text・同じ入力での追加参考計測では、ロード1,614.151ms、
全行レイアウト2,495.830ms、100,000回の位置検索71.297msだった。
`--edits 100`（既定値）は前方／末尾で挿入と削除を100回ずつ実行する。
各200操作の時間は前方1.021ms、末尾1.469ms、最後の一組のUndo＋Redoはそれぞれ
0.003ms／0.002ms。時間にはlength、行数、末尾行offset、挿入位置と本文の検査も含む。
変更前の編集時間は測定していないので、改善率を示す数値ではない。
拡張書記素対応を加えた段階の2回ではロード1,562.814／1,971.957ms、全行レイアウト
3,134.494／3,633.293ms、位置検索144.857／120.630ms、前方200編集1.060／0.989ms、
末尾200編集1.459／1.421msだった。その後、ASCIIループ内の文字列への重複アクセスを
減らした最終コードの1回は、ロード1,517.087ms、全行レイアウト1,083.298ms、
位置検索66.824ms、前方200編集1.004ms、末尾200編集1.448msだった。
いずれもサイズ・行数・検索位置・編集結果の照合に成功。測定回数が少なく、実行間の
